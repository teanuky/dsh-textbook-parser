# textbook-parser：用「问题驱动迭代」拆解整本理工科教材

## 0. 一句话方法

教材不是名词表，而是一条**连续的问题解决链**：每一章、每一节、每一个知识点，都是因为**上一环方案存在某个具体缺陷**才被发明出来。
把整本书拆成 `全书总纲 → 章 → 节 → 知识点` 四层，每层都回答「它为了解决上一环的什么缺陷而来」，禁止孤立罗列定义。

每层还要配**生活类比**（全书 / 章 / 节 / 知识点）与**可自测的多题型例题**（每节 4-6 道），让读者先懂「为什么需要它」，再能动手算。
每个知识点还要写**可自学详解**（`detail`）+ 学习要点 + 推导思路 + 易错辨析 + 考法提示，并用 `important` 标出 ★ 重点（全书 30%–45%、每节至少 1 个），方便复习抓主线。

## 1. 主线原则（写任何字段前先想清楚）

1. **循环迭代**：总目标 → 初代方案（有缺陷）→ 修复方案（获得能力，但产生新缺陷）→ 下一个修复 → …… 直到教材终点。
2. **每层都要有缺陷指向**：
   - 章：`solves` 写「上一阶段方案的具体缺陷」，`remainingGap` 写「本章方案仍存短板，即下一章的引入动机」；
   - 节：`subProblem` 写「本节要解决的子矛盾」；
   - 知识点：`solves` 写「它诞生要解决的问题 / 前方案哪里不行」。
3. **前后闭合**：上一章的 `remainingGap` 必须能对上下一章的 `solves`；上一节的 `remaining` 对上下一节的 `subProblem`；上一知识点的 `next` 对上后一知识点的 `solves`。
4. **具体、可背、可串**：面向工科大学生复习，一句话说清「旧方案哪里痛 → 新方案怎么修 → 代价是什么」，不写「很重要」「需掌握」这类空话。
5. **生活类比必须映射回技术概念**：每个 `analogy` 先给生活场景，再用半句到一句明确对应到数据/公式/系统行为，不能只写比喻不解释。篇幅：知识点 2-4 句，节 1-3 句，章/全书 2-4 句。

两个短例（只是示范写法，实际以教材原文为准）：

- **模电**：目标「放大微弱信号」→ 初代方案「单管共射放大器」（缺陷：增益随温度漂移、带宽窄）→ 修复「负反馈」（获得稳定增益与展宽带宽，新缺陷：可能自激振荡）→ 修复「频率补偿 / 相位裕度设计」→ ……。类比：负反馈像汽车定速巡航——不是把油门焊死，而是盯着实际车速不断微调。
- **信号与系统**：目标「分析线性时不变系统对任意激励的响应」→ 初代方案「时域冲激分解 + 卷积」（缺陷：微分方程求解繁琐，难以看出频率选择性）→ 修复「傅里叶变换」（新缺陷：增长型信号不收敛）→ 修复「拉普拉斯变换 / z 变换」→ 新缺陷「只能处理线性时不变系统」→ ……。类比：时域像逐帧看录像，频域像把声音分解成高低音——同一段音乐换个维度就一目了然。

## 2. 输入类型处理

| 用户给的东西 | 处理方式 |
| --- | --- |
| 教材名（如「信号与系统 郑君里第三版」） | 按公开的教材目录与学科主线建 12 章骨架；每章先写章级字段（含 `analogy`），再逐章细化。 |
| 目录截图 | 先 OCR/识别章名、节号、节名，转成 `book.json` 的 chapters/sections 骨架；识别不确定的章名照实写，并在 `remainingGap` 注明待核对。 |
| 单章文本 | 允许只拆这一章：向上从教材名/章号推断并写出全书主线与本章在链中的位置（`requires`/`solves`），向下在 `remainingGap` 说明本章承接的后续内容。 |
| PDF 全文 / 长文本 | 先通读目录与每章开头建立骨架，再分章精读；一章一次 `save_chapter`，不要一次性把全书塞进一次调用。 |

统一动作：**先确定教材元信息**（书名、版本/作者、册数、科目），**再建全书骨架**，**最后逐章填肉**。
无论输入是哪种，最终都要写全扩展字段：全书/章/节/知识点的 `analogy`、每节 `summary` 与 `examples`，以及每个知识点的 `important` / `detail` / `keyPoints` / `derivation` / `mistakes` / `examTips`。

## 3. 强制工作流程（必须用 `textbook_archive` 工具落库）

> **硬性要求**：拆解结果只能通过 `textbook_archive` 工具写入插件数据目录；**不要手写 JSON 到插件目录**，也不要改包内 `data/`（内置示例只读）。
> 用户打开侧边栏「教材知识框架」面板时，读的就是工具写入的数据。

### 步骤 1：确认教材元信息
书名、版本/作者、科目、册数、章数。id 用 kebab-case（如 `signals-systems-zheng`），一旦确定不要变。

### 步骤 2：`save_book` 写全书总纲 + 章/节骨架（先做一次）

```jsonc
textbook_archive({
  "action": "save_book",
  "book": {
    "schemaVersion": 1,
    "id": "signals-systems-zheng",
    "title": "信号与系统",
    "subtitle": "郑君里 · 第三版",
    "subject": "电子信息",
    "tags": ["信号与系统", "变换域"],
    "overview": {
      "goal": "……2-4 句……",
      "pain": "……2-4 句……",
      "mainline": "……一句话链路……",
      "analogy": "……用生活类比讲整本书的主线/意义，2-4 句……",
      "chain": [ { "step": "……", "detail": "……", "defect": "……" } ]
    },
    "chapters": [
      {
        "id": "ch01", "number": 1, "title": "绪论",
        "solves": "……", "requires": ["微积分"], "gain": "……", "remainingGap": "……",
        "analogy": "……本章生活类比，2-4 句……",
        "sections": [ { "id": "1.1", "title": "信号与系统", "subProblem": "……", "pointCount": 2 } ]
      }
    ],
    "stats": { "chapters": 12, "sections": 90, "points": 420 }
  }
})
```

要点：`chapters` 按教材实际章数写全（信号与系统为 12 章，id `ch01`…`ch12`；可先只写有把握的章，其余保留章骨架之后再补）；`stats` 可以先填估算值（工具在保存章后会自动重算）；`pointCount` 先按目录估算，保存章文件后工具会同步为实际值；每章一定写 `analogy`（与章文件保持一致）。

### 步骤 3：逐章 `save_chapter`（一章一次，写完整章）

```jsonc
textbook_archive({
  "action": "save_chapter",
  "bookId": "signals-systems-zheng",
  "chapter": {
    "id": "ch01", "number": 1, "title": "绪论",
    "solves": "……", "requires": ["微积分"], "gain": "……", "remainingGap": "……",
    "analogy": "……与 book.json 本章 analogy 一致……",
    "chain": [ { "from": "……", "to": "……", "label": "修复" } ],
    "sections": [
      {
        "id": "1.1", "title": "信号与系统", "subProblem": "……", "requires": [], "remaining": "",
        "summary": "本节一句话总览：……\n① 知识点一：一句话作用……\n② 知识点二：一句话作用……",
        "analogy": "……本节生活类比，1-3 句……",
        "examples": [
          { "id": "1.1-e1", "type": "概念判断", "source": "教材例题改编", "question": "……", "answer": "步骤：…… 结论：……", "note": "可选：易错提示" }
        ],
        "points": [
          {
            "id": "1.1.1", "title": "……",
            "solves": "……", "meaning": "……", "analogy": "……",
            "important": true,
            "detail": "……350-800 字可自学详解（为什么需要 / 核心结论 / 怎么用 / 与前后关系）……",
            "keyPoints": ["要点一：必须记住的结论……", "要点二：解题步骤……", "要点三：易错点……"],
            "derivation": "……推导/证明思路 100-300 字（纯概念类可写空字符串）……",
            "mistakes": "……易错辨析 80-200 字……",
            "examTips": "……考法/应用提示 50-150 字……",
            "formula": "……", "application": "……",
            "example": { "question": "……", "answer": "……" },
            "prerequisites": [], "limitation": "", "next": ""
          }
        ]
      }
    ]
  }
})
```

- 一章必须一次写完整（同一个 `chNN.json` 会被整文件覆盖，分两次会丢前一次内容）。
- 可以只先写有把握的章；`book.json` 的 `stats` 与节 `pointCount` 会随每一章保存自动更新。
- 保存后看工具返回的全书统计，确认章数/节数/知识点数在增长。
- 每节的 `summary` / `analogy` / `examples` 与每个知识点的 `analogy` 是 **v1.1 必写字段**；每个知识点的 `important` / `detail` / `keyPoints` / `derivation` / `mistakes` / `examTips` 是 **v1.2 必写字段**（校验器对旧数据兼容，但本 skill 产出的新内容必须齐全；`derivation` 纯概念类可写 `""`）。

### 步骤 4：处理校验错误（不要绕过）

校验失败时工具会返回类似：

```text
第 ch03 章数据校验未通过（chapters/ch03.json）（3 处）：
- sections[1].points[0].analogy 必须是非空字符串（当前：缺失）
- sections[1].summary 必须是非空字符串（当前：缺失）
- sections[1].examples[0].answer 必须是非空字符串（当前：""）
```

按字段路径逐条修正后**重试同一个 action**；不要删字段糊弄、不要改用其它方式写文件。

### 步骤 5：全部章完成后收尾

- 再调一次 `save_book`（book.json 用实际章数/节数/知识点数；工具会按已保存的章文件重算 `stats`）；
- 调 `list_books` 确认书在列表里、统计合理；
- 调 `get_book` + `bookId` 抽查全书结构，加 `chapterId`（如 `ch01`）抽查单章详情（含新字段）。

## 4. 固定输出层级与每层必填字段

用户要求的层级模板（四层，逐层下钻）：

```text
全书总纲（总目标 / 原始痛点 / 迭代主线 / 生活类比）
└─ 第 X 章（解决什么缺陷 / 前置依赖 / 获得能力 / 仍存短板 / 生活类比）
   └─ X.1 小节（子问题 / 生活类比 / 知识点汇总 / 典型例题 / 前置 / 遗留不足）
      └─ 知识点（★重点 / 诞生要解决的问题 / 含义 / 详细讲解 / 学习要点 / 生活类比 / 公式 / 推导思路 / 应用 / 易错辨析 / 考试·应用提示 / 例题 / 前置 / 遗留不足 / 下一环）
```

| 层级 | 必填字段（对应数据） | 内容要求 |
| --- | --- | --- |
| 全书 | `overview.goal` / `overview.pain` / `overview.mainline` / `overview.analogy` / `overview.chain[]` | 总目标 2-4 句；原始痛点 2-4 句；主线一句话链路；`analogy` 用生活类比讲全书在解决什么，2-4 句；chain 至少 1 项（建议 3-6 项），每项 `step`/`detail`/`defect` 都要具体 |
| 章 | `title` / `solves` / `requires[]` / `gain` / `remainingGap` / `analogy` / `sections[]` | `solves` 指向上一阶段的具体缺陷；`remainingGap` 必须是下一章的引入动机；`analogy` 2-4 句且与 book.json 本章一致 |
| 节 | `title` / `subProblem` / `requires[]` / `remaining` / `summary` / `analogy` / `examples[]` / `points[]` | `subProblem` 1-2 句；`summary` 一句总览 + 逐条列出本节知识点及一句话作用（`\n` 分条）；`analogy` 1-3 句；`examples` 4-6 道（至少 3 道）覆盖多题型；`remaining` 可为空字符串 |
| 知识点（基础） | `title` / `solves` / `meaning` / `analogy` / `formula` / `application` / `example{question,answer}` / `prerequisites[]` / `limitation` / `next` | `solves` 必须具体到「前方案哪里不行」；`meaning` 2-5 句；`analogy` 2-4 句生活类比并映射回技术概念；`formula` 用纯文本 Unicode（如 `H(jω)=1/(1+jωRC)`），无公式填空字符串；`example` 必须可算；`limitation`/`next` 可为空字符串 |
| 知识点（v1.2 详解/星标） | `important` / `detail` / `keyPoints[]` / `derivation` / `mistakes` / `examTips` | `important` 布尔值：true 时侧栏/导出显示 ★ 与「重点」徽标；`detail` 350-800 字可自学详解；`keyPoints` 3-6 条（每条 20-60 字）；`derivation` 推导/证明思路 100-300 字（纯概念可 `""`）；`mistakes` 易错辨析 80-200 字；`examTips` 考法/应用提示 50-150 字 |

另加一章一条「章内迭代链」：`chain[]` 至少 2 项，格式 `{ "from": "上一方案/缺陷", "to": "本章知识点或方案", "label": "修复/替代/推广" }`，把本章的方案继承关系串起来。

每节例题（`examples[]`）每项格式与要求：

```json
{
  "id": "1.1-e1",
  "type": "概念判断|计算|推导证明|综合应用|易错辨析|设计/工程",
  "source": "教材例题改编|课后习题改编|典型题",
  "question": "题干（具体、可算/可判断）",
  "answer": "解答步骤 + 最终答案（2-8 句，不能写“略”）",
  "note": "可选：易错提示/考点"
}
```

- 数量 4-6 道（至少 3 道），同一节 `id` 唯一（建议 `"1.1-e1"` 形式）；
- `type` 至少覆盖 2 类（建议 3 类以上：概念判断、计算、推导证明、综合应用、易错辨析、设计/工程）；
- `source` 必写，标注题目来源性质（`教材例题改编` / `课后习题改编` / `典型题`）；
- 例题必须贴合本节知识点，`question` 具体可算/可判断，`answer` 给步骤与结果，不能写「略」。

**重点星标（★）规则**：

- 每个知识点必须写 `important`（boolean）：复习主线的核心知识点标 `true`，侧栏与导出网页会在标题前显示 ★ + 「重点」徽标；非重点写 `false`，不要留空、不要全标 true。
- 全书重点比例控制在 **30%–45%**；**每一节至少 1 个重点**（优先标该节最核心、最常考的第一个知识点）。
- 重点判断标准：承载本节核心方法/结论、考试高频、后续章节直接依赖的知识点。

每个知识点的 v1.2 详解字段（必须写全，校验器会检查类型；旧数据缺字段仍兼容）：

```json
{
  "important": true,
  "detail": "350-800 字详细讲解，面向自学：①它解决什么问题/为什么需要；②核心内容与关键结论（含必要公式）；③怎么用（步骤/判别法/计算套路）；④与前后知识点的关系。要具体、可复述，禁止空话。",
  "keyPoints": ["必须记住的结论……", "解题步骤 / 套路……", "容易错的地方……"],
  "derivation": "推导/证明/思路 100-300 字；定理、公式、方法类必写；纯概念类可写空字符串。",
  "mistakes": "易错辨析 80-200 字：常见错误、混淆点、边界条件。",
  "examTips": "考法/应用提示 50-150 字：常见题型、解题入口、工程/后续课程用途。"
}
```

## 5. 数据 schema 摘要与最小完整示例

数据分两个文件（都由工具写，UTF-8、纯 JSON、2 空格缩进、无注释、无尾逗号）：

- `book.json`：全书总纲 + 章/节骨架（chapters 数组、每章 sections 元信息、`overview.analogy`、每章 `analogy`）；
- `chapters/chNN.json`：该章全部节与知识点详情（章 `analogy`、节 `summary`/`analogy`/`examples`、知识点 `analogy` 与 v1.2 的 `important`/`detail`/`keyPoints`/`derivation`/`mistakes`/`examTips`）。

下面是**最小结构示例**（为了篇幅 book 只保留 ch01；真实拆解里 `chapters` 必须包含教材全部章，信号与系统为 12 章）：

```json

  "id": "signals-systems-zheng",
  "title": "信号与系统",
  "subtitle": "郑君里 · 第三版",
```

## 7. 科目适配提示（链的默认骨架，以教材实际章节为准）

- **模电**：理想放大器目标 → 单管放大（缺陷：工作点漂移、增益不稳）→ 负反馈（新缺陷：自激）→ 频率补偿/稳定性 → 差分放大/运放 → 功率与电源。类比：负反馈像定速巡航；频率补偿像给容易晃的方向盘加阻尼。
- **数电**：逻辑抽象（0/1 与真值表）→ 组合逻辑（缺陷：无记忆）→ 时序逻辑/触发器 → 有限状态机 → 可编程逻辑与接口。类比：组合逻辑像计算器按键直出结果，时序逻辑像带记忆的自动售货机。
- **信号与系统**：信号分解（冲激/阶跃）→ 卷积 → 傅里叶变换（缺陷：不收敛）→ 拉普拉斯/z 变换 → 系统函数与稳定性 → 采样与离散处理。类比：时域看录像、频域听音高、复频域给系统做「全身 CT」。
- **复变函数**：复数与解析函数（缺陷：可导性太强）→ 复积分/柯西定理 → 幂级数/洛朗级数 → 留数定理 → 积分计算与映射。类比：解析函数像「无缝拼图」，微小的局部信息能推出整块图案。
- **电路**：KCL/KVL 与元件约束 → 网络定理（叠加/戴维南）→ 动态电路（一阶/二阶）→ 正弦稳态相量 → 频域/复频域分析。类比：网络定理像把复杂人群简化成「一个等效代言人」。

## 8. 失败处理与边界

- **校验失败**：逐条读工具返回的字段路径，改对应值后重试；不要删字段、不要手写文件绕过。
- **内容太多/太长**：分章增量保存，一章一次写完整；宁可多次调用，不要一次塞整本书。
- **不确定的内容**：只写有把握的章节；拿不准的事实宁可少写，也不要编造公式或例题答案。可在 `remainingGap`/`limitation` 里注明「待核对」。
- **找不到 bookId**：报「未找到教材」时，先 `save_book` 建书，再 `save_chapter`；用 `list_books` 确认 id。
- **只读边界**：内置示例教材（`source: "bundled"`）不可 `delete_book`；要改就换一个 bookId 另存。用户数据目录为 `$DSH_HOME/textbook-parser/books/<bookId>/`，不要写其它路径。
- **用户核对**：保存完成后告诉用户「已写入，可在侧边栏『教材知识框架』查看；需要离线学习时点面板顶栏『导出』——交互式 HTML 与侧栏体验一致（嵌套卡片、逐层下钻、面包屑/返回、答案折叠、★ 重点标注，自包含无外链，手机可离线打开），也可导出 Word / PDF」，并给出书的 id 与统计（章/节/知识点/重点数）。
